## Overview
This project involved designing and implementing a full‑stack database system for the Wounded War Heroes organization. The system centralizes veteran information, event participation, volunteer activities, service requests, and contact history. It replaces scattered spreadsheets with a structured database and an interactive dashboard that provides real‑time insights through charts, statistics, and searchable records.

## Abstract
The system integrates multiple data categories including veterans, trip events, volunteer events, participation records, and contact history. A MySQL database stores all structured data, while a web‑based interface built with HTML, CSS, and JavaScript allows staff to interact with the system. Backend logic is handled using Python or PHP.

The dashboard highlights key metrics such as total veterans, event counts, participation trends, and service request statuses. Users can search for veterans, track event involvement, review service dog requests, and analyze engagement over time.  

## Introduction
The Wounded War Heroes Database supports a national organization dedicated to assisting wounded veterans. The system provides centralized storage for veteran records, event details, participation logs, and service requests. It also includes dashboards for analyzing trends in attendance, volunteer activity, and service support.

Primary users include administrators, staff members, and event coordinators who need tools for searching records, managing events, tracking service requests, and generating reports.

## Database Design
The database includes multiple interconnected tables:

- Veteran  
- TripEvent  
- TripParticipation  
- VolunteerEvent  
- EventVolunteer  
- VeteranContactYear  
- PotentialMember  
- ServiceDog  
- DeerMount  

Each table follows BCNF normalization with clearly defined functional dependencies. The ER diagram includes relationships for veteran participation, service requests, volunteer involvement, and contact history.

### User Requirements
- Store detailed veteran records  
- Track trip and volunteer events  
- Log participation for each veteran  
- Manage service requests  
- Provide search functionality  
- Display dashboards and analytics  

### Business Rules
- Veterans may participate in multiple events  
- Service requests link to exactly one veteran  
- Events are categorized as trip or volunteer  
- Duplicate participation records are not allowed  

### Assumptions
- All IDs are unique  
- Only authorized staff modify data  
- Contact history is optional  
- Contact information is valid  

### Constraints
- Foreign keys must match existing records  
- Email and phone must be unique  
- Event dates must be valid  
- Participation requires both VeteranID and EventID  
- Deleting linked records is restricted
